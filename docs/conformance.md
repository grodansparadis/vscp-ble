# Conformance and tests

## Shared vectors

`tests/vectors/vectors.json` (and the same data as C arrays in
`vectors.h`) are generated by `tools/gen_vectors.py` from the Python codec,
with AES-CCM from `python3-cryptography`. The C library must reproduce every
frame byte for byte, so the vectors tie three implementations together:
the Python codec, the C library with OpenSSL, and the C library with the
reference AES-CCM.

| Vectors | Content |
| --- | --- |
| `e1_a`, `e1_b` | Spec section 5.7 vectors A and B (checked against the spec text) |
| `e1_max` | 222 data octets, sequence 0xFFFFFFFF |
| `l0_spec` | Spec section 4.4 example |
| `a2_n3`, `a2_n0`, `a2_max` | A2 known answers (N = 3, 0, 200): exact nonce and AAD construction |
| `f1_223`, `f1_1024` | Spec section 9.5 fragment layouts |
| `g1_n3`, `g1_max` | G1 records and their fragments at ATT MTU 23, 185, 247, 517 |
| `g1_hello` | A HELLO control message |

Test key: key id 1, key `000102…0f`, nonce prefix `a0a1a2a3a4`, GUID
`00:01:…:0F`, Company Identifier 0xFFFF. Test only.

`tools/gen_vectors.py --check` (run in CI) fails if the files are out of
date.

## C tests (GoogleTest)

```bash
cmake -S . -B build && cmake --build build -j && ctest --test-dir build --output-on-failure
```

The suite builds twice, against the configured backend (OpenSSL when found)
and against the reference AES-CCM. It covers the spec's required negative
tests:

- **E1** (5.7): version 2, flags 0x01/0x80, zero GUID, N = 223, AD Length
  not 33 + N, truncated data, extra octets, several candidate frames,
  truncated reports.
- **A2** (7.7): known answers for N = 0, 3, 200; every single modified octet
  of a frame (header, ciphertext, tag) is rejected without touching the
  replay state; unknown, revoked and other-GUID keys; epoch range; wrong
  key and prefix; reserved flags; malformed lengths; replayed and
  out-of-order sequences; epoch advance and lower epoch after advancing;
  replay state after a restart; persistence failure (fails closed, clears
  the plaintext); counter exhaustion and epoch advance (counter tests).
- **F1** (9.5): both vectors; out-of-order and duplicate fragments;
  conflicting bytes and metadata; T = 1025, K = 9, wrong offset, bad
  FIRST/LAST, nonzero reserved octets, truncated structure; the absolute
  deadline; clock wrap; the two-message limit; the completion cache.
- **G1** (6.7): records and fragments at MTU 23 to 527; maximum payload;
  missing LAST, early LAST, gaps, overlaps and duplicates; a second
  transaction while one is in progress; timeouts; disconnect and reconnect;
  permission failures; HELLO negotiation and its errors; NOT_READY before
  HELLO; oversize events; client-only opcodes; Event TX fragment size at a
  large MTU and reassembly by the client.

## Sanitizers and fuzzing

```bash
cmake -S . -B build-asan -DVSCP_BLE_SANITIZE=ON -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
tests/fuzz/run.sh 600          # libFuzzer, seconds
```

`tests/fuzz/fuzz-receive.c` drives every receive path with untrusted
input: advertising data sets, E1, L0, A2 (with a key), F1 sequences, G1
fragment sequences, control messages and whole G1 server sessions. The
corpus is seeded from the vectors. CI runs 60 s per push; the first local
run executed 2.5 million inputs without a finding.
